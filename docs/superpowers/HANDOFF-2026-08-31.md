## 2. 지금 최우선 — 취소가 듣지 않는 버그 (미해결)

### 사용자 보고

> "받는 중에 취소를 누른다" 는 취소 버튼은 클릭이 되지만 실제 취소가 되지 않아.

SSMS 21에서 `git@github.com:moondae815/dbvc.git`를 `D:\dbvc-repos\dbvc-clone-test`로
Clone 하는 도중 취소를 눌렀는데 clone이 그대로 끝났다.

### 이미 확인한 증거 (다시 조사하지 말 것)

1. `D:\dbvc-repos\dbvc-clone-test`가 **그대로 남아 있다** — 260커밋·154파일·`.git` 1.1MB.
   clone이 끝까지 성공했다.
2. `%APPDATA%\DBVC\mappings.json`에 **`StablecoinGateway` 매핑이 만들어졌다.**
3. 이 둘은 `ViewChangesViewModel.CloneAndConnect`의 `onSucceeded` 경로에서만 생긴다.
   즉 `GitManager.CloneRepository`가 `Repository.Clone` **직후에 하는
   `cancellationToken.ThrowIfCancellationRequested()`조차 발동하지 않았다.**
   → 취소가 "늦게 걸린" 것이 아니라 **토큰이 취소된 상태가 아니었다.**
4. 기존 테스트 `CloneRepository_RemovesTheFolderItCreated_WhenCancelledWhileRunning`은
   **파일 경로 원격**을 쓴다. libgit2의 local 전송을 타서 전송 단계 보고가 없을 수 있고,
   그래서 이 테스트는 checkout 보고를 통한 **clone 이후 경로**만 검증한다.
   **`OnTransferProgress`가 `false`를 돌려주어 전송을 끊는 경로는 한 번도 테스트된 적이 없다.**
5. 이 개발 셸에서는 SSH가 안 된다(`Permission denied (publickey)`, `SSH_AUTH_SOCK` 없음).
   SSMS는 되므로 **실기 재현은 사용자만 할 수 있다.**

### 남은 가설 (아직 판정 안 됨)

- **가설 A — 전송 콜백이 아예 안 불린다.** 그러면 전송 중 토큰을 폴링하는 자리가 없어
  취소가 물리적으로 불가능하다. 진행 문구가 `원격 저장소를 받는 중...`에서
  `받는 중... n/m 객체`로 **안 바뀌었다면** 이쪽이다.
- **가설 B — 저장소가 너무 작아 창이 없었다.** 1.1MB면 SSH 전송이 1초 안팎이라
  누를 틈이 실질적으로 없다. 이 경우 코드는 정상이고, 문제는 "너무 늦게 눌렀는데
  아무 안내도 없다"는 UX다.

### 사용자에게 물어봐야 할 것 (아직 답 못 받음)

1. 진행 문구에 **숫자가 떴는가** (`받는 중... 12/260 객체`) 아니면 그대로였는가?
2. 취소를 누른 뒤 **`취소하는 중...`으로 바뀌었는가**?

### 판정용 실기 절차 (사용자가 해야 함)

```powershell
# SSMS를 닫은 뒤
Remove-Item -Recurse -Force D:\dbvc-repos\dbvc-clone-test
# %APPDATA%\DBVC\mappings.json 에서 StablecoinGateway 항목을 지운다
```

SSMS를 다시 띄우고 **큰 저장소**로 받아 본다 — 창을 크게 벌려야 판정이 된다:

```
git@github.com:dotnet/runtime.git
```

수백 MB라 전송이 한참 돈다(끝까지 받을 필요 없다). 볼 것:

- 숫자가 올라가는가
- 취소를 누르면 **몇 초 안에 멈추는가**
- 멈춘 뒤 대상 폴더가 **사라지는가**, 매핑이 **안 생기는가**

**이 결과가 나오기 전에는 코드를 고치지 않는다** (systematic-debugging의 철칙:
근본 원인 규명 없이 수정 없음).

### 관련 코드 위치

- `src/DBVC.Core/GitManager.cs` — `CloneRepository`
  (`options.FetchOptions.OnTransferProgress`가 `!cancellationToken.IsCancellationRequested`를
  반환한다. `false`면 libgit2가 `UserCancelledException`을 던지고, 그것을 `catch`에서
  `OperationCanceledException`으로 바꾼다.)
- `src/DBVC.Vsix/ViewModels/ViewChangesViewModel.cs`
  - `Cancel()` (약 623행) — `_cancellableOperation?.Cancel()` + `ProgressText = "취소하는 중..."`
  - `CloneAndConnect` (약 1026행) — `CloneProgressRelay`가 `Transferring`일 때만
    `Busy.IsCancellable = true`를 유지하고 `CheckingOut`으로 넘어가면 끈다.
  - `CancelCommand = new RelayCommand(Cancel, () => IsBusy && Busy.IsCancellable)` (약 104행)
- `src/DBVC.Vsix/ViewModels/BusyState.cs` — 3차에서 도입. `IsCancellable`, `ProgressText` 보유.

### 알아 둘 라이브러리 함정

- `TransferProgressHandler`는 `bool` 반환(false면 중단), `CheckoutProgressHandler`는 `void`
  — **checkout 단계는 끊을 수 없다.**
- `LibGit2Sharp.UserCancelledException`은 `System.OperationCanceledException`을
  **상속하지 않는다.**
- `Repository.Clone`은 work tree가 아니라 `.git` 경로를 돌려준다.

## 6. 새 에이전트가 반드시 지켜야 할 것

`CLAUDE.md`에 전부 있지만, 어기면 조용히 깨지는 것들만 다시 적는다.

- **패키지 버전을 올리지 않는다** — `Microsoft.Data.SqlClient 5.1.5`,
  SMO `171.30.0`, LibGit2Sharp `0.32.0`. 올리면 SSMS에서 **어떤 DB에도 접속되지 않는다.**
- **인증 정보를 디스크에 쓰지 않는다.** `SessionCredentialStore`는 메모리 전용이고
  값의 유일한 출처는 SSMS 개체 탐색기다.
- **Git 인증은 SSH만.** HTTPS 원격은 네트워크를 타기 전에 거부하고 `RemoteDiagnostics`가 안내한다.
- **사용자에게 보이는 모든 문구는 한국어.** 예외 메시지·버튼·ToolTip·컬럼명 포함.
- 주석은 **"왜"만**, 한국어 평서문.
- 커밋 메시지: 한국어 명령형 현재시제 + 스코프 — `fix(core): 전송 중 취소를 실제로 끊는다`
- 테스트 이름은 영어 `Method_Result_WhenCondition`.
- TDD: 실패하는 테스트 → 최소 구현 → 통과 → 커밋.
- **CI가 검증하지 않는 것:** WPF 렌더링, VS 패키지 로딩, `.vsct` 메뉴 등록, SSMS 통합, 실제 DB 연결.
  이 영역을 건드렸다면 SSMS 21에서 직접 눌러 보기 전에 "동작한다"고 말하지 않는다.
