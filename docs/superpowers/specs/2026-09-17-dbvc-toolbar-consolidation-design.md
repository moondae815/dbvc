# 도구 창 버튼을 역할별로 묶는다 — 설계

> **성격: 화면 재배치.** Core와 `MappingPolicy`는 바꾸지 않는다. 명령(`ICommand`)과 그 `CanExecute`도
> 그대로 두고, 버튼이 놓이는 자리와 모양만 바꾼다. 배포·감사 패널(`DeploymentPanelGrid`)은 0.8.0의 병합
> 영역을 포함해 배치를 바꾸지 않는다(2.7) — 두 화면이 맞닿는 곳(맨 윗줄)만 맞춘다.

## 1. 문제

기능이 쌓이면서 개발 클론 화면의 버튼이 14개가 되었고, 전부 같은 크기로 세 줄에 흘러내린다
(0.7.2 기준 스크린샷).

```
[연결] localhost.Northwind — Windows 인증[새 브랜치][브랜치 전환]   브랜치: develop  DBVC 0.7.2
[새로고침][전체 다시 추출][____________][AI 생성][Commit]
[되돌리기][무시][Pull][Push][원격 확인][배포 스크립트][롤백 스크립트]
☑ 다른 사람 변경도 보기
```

- **빈도가 구분되지 않는다.** 매번 누르는 `새로고침`·`Commit`과 가끔 누르는 `전체 다시 추출`·`롤백
  스크립트`가 같은 무게로 보인다.
- **적용 대상이 보이지 않는다.** `되돌리기`·`무시`·`배포 스크립트`·`롤백 스크립트`는 **체크한 항목**에
  작용하는데(`CanDiscard`·`CanGenerateScript`가 `Changes.Any(c => c.IsSelected)`로 판정), 버튼이 목록과
  떨어져 `Pull` 사이에 끼어 있다. `무시`는 공용 DB를 함께 쓰는 모두에게 적용되는 버튼인데 네트워크
  버튼과 나란히 있다.
- **커밋 메시지 칸에 이름이 없다.** 너비 240 고정의 빈 칸이라 무엇을 적는 곳인지 화면이 말하지 않는다.
- **대상 표시가 잘린다.** `TargetLabel` 바로 뒤에 `새 브랜치`가 붙어 "Windows 인증"이 버튼에 가린다.

## 2. 결정

### 2.1 버튼을 네 무리로 나누고, 무리 단위로 줄바꿈한다

| 무리 | 담는 것 | 자리 |
| --- | --- | --- |
| 대상 | 연결, 브랜치 메뉴, 버전 | 맨 윗줄(지금 자리) |
| 저장소 동기화 | 새로고침(+전체 다시 추출), Pull, Push, 원격 확인 | 변경 목록 도구 줄 |
| 커밋 | 커밋 메시지, AI 생성, Commit | 그 아래 한 줄 |
| 체크한 항목 | 체크 개수, 되돌리기, 무시, 스크립트 메뉴, 다른 사람 변경도 보기 | 목록 바로 위 |

버튼 하나하나가 아니라 **무리가 통째로 다음 줄로 내려간다.** 좁게 도킹했을 때 `Pull`만 윗줄에 남고
`Push`가 아랫줄로 떨어지는 식의 분리가 없어야 한다.

### 2.2 가끔 쓰는 것만 메뉴로 접는다

접는 기준은 "자주 쓰지 않는다" **그리고** "잘못 누르면 비용이 크거나 같은 계열의 변형이다"이다.

- `전체 다시 추출` → `새로고침` 옆 `▾` 메뉴. 새로고침의 느린 변형이고, 누르면 DB 전체를 긁는다.
- `배포 스크립트`·`롤백 스크립트` → `스크립트 ▾` 메뉴 하나. 같은 산출물의 두 방향이다.
- `새 브랜치`·`브랜치 전환` → 브랜치 이름 자체를 버튼으로 만든 `develop ▾` 메뉴.

`Pull`·`Push`·`원격 확인`·`되돌리기`·`무시`는 접지 않는다. 앞의 셋은 티켓 한 바퀴마다 누르고, 뒤의
둘은 위험 표시(확인 대화상자)가 이미 있어 메뉴 속에 숨기면 오히려 존재를 모른다.

### 2.3 우클릭 메뉴를 쓰지 않는다

처음 떠올린 안은 되돌리기·무시를 행 우클릭으로 옮기는 것이었다. 택하지 않는다. 명령은 **체크한
항목**에 작용하는데 우클릭은 **클릭한 행**을 가리키므로, 3개를 체크하고 다른 행에서 우클릭해
`되돌리기`를 누르면 무엇이 되돌아가는지 화면이 거짓말을 한다. 명령의 대상을 바꾸는 것은 이 설계의
범위(재배치)를 넘는다.

### 2.4 체크 작업 줄은 항상 보이고, 체크가 없으면 잠긴다

체크했을 때만 줄을 띄우는 안은 평소 한 줄을 아끼지만, 체크할 때마다 목록이 아래로 밀리고 처음 쓰는
사람은 기능이 있는지 모른다. 위치가 고정된 쪽을 택한다(사용자 결정, 2026-09-17). 잠금은 기존
`CanExecute`가 그대로 맡는다 — 화면에 `IsEnabled`를 따로 걸지 않는다(같은 판정이 두 곳에 생긴다).

### 2.5 원격 숫자는 버튼에 붙이되, 자동으로 채우지 않는다

`원격 확인`은 **누를 때만 네트워크를 쓴다**(README "원격 확인", 새로고침에 붙이면 응답 없는 원격이
목록 보기까지 느리게 만든다). 이 규칙은 그대로다. 바뀌는 것은 결과를 보여 주는 자리뿐이다 — 지금은
윗줄 오른쪽의 `받을 커밋 2개 · 올릴 커밋 1개` 글자인데, 그 숫자가 가리키는 행동 옆으로 옮긴다.

```
확인 전:  [Pull] [Push] [원격 확인]
확인 후:  [Pull ↓2] [Push ↑1] [원격 확인]
```

숫자를 지우는 시점은 지금 `RemoteStatusText = null`인 여섯 자리(대상 변경, 원격 확인 실패, Pull 후,
Push 후, 브랜치 조작 후, 커밋 후)와 정확히 같다. 낡은 숫자를 최신인 척 보여 주지 않는다는 기존 원칙을 옮겨 온다.

### 2.6 아이콘은 쓰지 않고 글자로 둔다

VS 이미지 카탈로그(`KnownMonikers` + `CrispImage`)는 `Microsoft.VisualStudio.Imaging` 참조를 더하고,
그 어셈블리가 SSMS 21 프로세스에서 해결되는지를 다시 실기로 확인해야 한다. 버튼 수를 줄이는 것이
목적이고 그것은 묶기만으로 달성되므로 들이지 않는다. `▾`·`↓`·`↑`는 Segoe UI에 있는 글자다.

### 2.7 배포 패널은 병합 영역까지 그대로 둔다

0.8.0에서 배포 패널에 병합 영역이 들어왔다([병합 설계](2026-09-17-dbvc-merge-in-deploy-clone-design.md)
3.5). 이 설계를 처음 쓸 때 "구현된 뒤 버튼이 늘었는지 따로 본다"고 미뤄 둔 것을 여기서 판정한다.

| 단계 | 버튼 |
| --- | --- |
| 병합(접히는 머리글 `병합 — 목적지: master`) | `병합할 브랜치 확인`, `병합` |
| 배포 | `차이 검사`, `배포 스크립트 저장...` |

**바꾸지 않는다(사용자 결정, 2026-09-17).**

- 버튼이 넷이고 이미 절차 순서(병합 → 검사 → 배포)대로 두 무리로 나뉘어 있다. 2.1이 개발 클론에
  세우려는 모양이 여기에는 이미 있다.
- 2.2의 접는 기준에 걸리는 것이 없다. 넷 다 배포 한 바퀴마다 누르고, `병합`은 원격을 바꾸는 버튼이라
  메뉴에 숨기면 안 된다.
- 병합 영역은 방금 실기 검증을 거쳤다. 모양만 맞추려고 고치면 그 검증을 다시 해야 한다.

**맞닿는 곳.** 두 화면이 함께 쓰는 것은 맨 윗줄뿐이다(아래 영역은 `ShowChangeList`와
`ShowDeploymentPanel`이 서로 배타로 고른다).

- 배포·감사 클론의 윗줄에도 `BranchMenuButton`(`master ▾`)이 보인다. 메뉴를 열면 두 항목이 잠겨 있고,
  ToolTip이 고정 브랜치라서 잠겼다고 말한다(3.2의 2). 병합 영역 머리글의 `목적지: master`와 이름이
  겹치지만 뜻이 다르다 — 윗줄은 **저장소가 지금 있는 곳**(`CurrentBranch`), 머리글은 **병합이 들어갈
  곳**(매핑의 고정 브랜치)이다. 둘이 어긋나면 차단 오버레이가 화면 전체를 덮으므로 사용자가 두 값이
  다른 채로 보는 일은 없다.
- `Pull ↓n`·`Push ↑n`은 개발 클론의 도구 줄에만 있다. `MergeAndPush`가 원격을 바꿔도 배포 패널에는
  낡을 숫자가 없다. 대상을 개발 클론으로 바꾸면 대상 무효화가 `LastRemoteStatus`를 지운다(2.5).
- 드롭다운 메뉴(`DropDownMenu`)와 새 버튼 모양(`Padding="8,1"`)은 배포 패널에 들이지 않는다. 배포
  패널의 `Padding="10,3"` 버튼과 개발 클론 도구 줄의 버튼 높이가 다른 것은 받아들인다 — 한 화면에
  함께 보이지 않는다.

## 3. 설계

### 3.1 배치

```
┌──────────────────────────────────────────────────────────────────────┐
│ [연결] localhost.Northwind — Windows 인증          [develop ▾] 0.7.2 │ 대상
│ (진행 표시 · 안내 · 배너 — 지금과 같다)                              │
├──────────────────────────────────────────────────────────────────────┤
│ [새로고침][▾]                          [Pull ↓2][Push ↑1][원격 확인] │ 동기화
│ [커밋 메시지__________________________________][AI 생성][Commit]     │ 커밋
│ 체크한 항목 3개 [되돌리기][무시][스크립트 ▾]  ☐ 다른 사람 변경도 보기│ 체크
│ ┌ 스테이징 │ 상태 │ 객체 │ 객체 유형 │ 변경자 ───────────────────────┐ │
```

- **대상 줄.** `새 브랜치`·`브랜치 전환` 버튼과 `BranchLabel`·`RemoteStatusLabel`을 없애고, 그 자리에
  `BranchMenuButton`(`{CurrentBranch} ▾`) 하나를 둔다. 버전 오른쪽 고정·세로 `Top` 정렬 규칙은 그대로다.
  브랜치를 모르면(`HasCurrentBranch` false) 버튼째 숨긴다.
- **동기화 줄.** 왼쪽 무리와 오른쪽 무리를 `DockPanel`로 가른다. 창이 좁아 한 줄에 들어가지 않으면
  오른쪽 무리가 통째로 다음 줄로 내려간다(2.1). 구현은 무리마다 `StackPanel`로 묶은 뒤 바깥을
  `WrapPanel`로 두는 방식을 기본으로 하고, 좌우 정렬이 `WrapPanel`에서 성립하지 않으면 왼쪽 정렬로
  물러선다 — 좌우 정렬은 보기 좋음이고, 무리 단위 줄바꿈은 요구사항이다.
- **커밋 줄.** 메시지 칸은 남는 너비를 모두 쓴다(`DockPanel`, `LastChildFill`). 칸이 비어 있으면
  회색 `커밋 메시지` 안내 글자를 겹쳐 보인다 — WPF `TextBox`에는 placeholder가 없으므로
  `TextBlock`을 같은 셀에 겹치고 `IsHitTestVisible="False"`로 둔다. 한 줄 입력은 그대로다.
- **체크 줄.** 맨 앞에 `체크한 항목 {n}개`. `다른 사람 변경도 보기`는 목록을 거르는 옵션이므로 이 줄
  맨 뒤로 온다. 오른쪽 끝에 붙이지 않고 `WrapPanel`로 흘린다 — `DockPanel`은 줄바꿈하지 않아 좁은 창에서
  버튼과 겹친다. 그 `Foreground` 규칙(셸 테마 브러시를 직접 받는다)은 그대로 옮긴다.

### 3.2 드롭다운 메뉴 세 개

`새로고침 ▾`, `스크립트 ▾`, `develop ▾`는 같은 방식이다: 버튼을 누르면 그 버튼에 붙은
`ContextMenu`를 버튼 아래(`Placement="Bottom"`)에 연다. 메뉴 항목은 기존 명령에 바인딩한다.

| 메뉴 | 항목 | 명령 |
| --- | --- | --- |
| `새로고침 ▾` | `전체 다시 추출 (느림)` | `RefreshAllCommand` |
| `스크립트 ▾` | `배포 스크립트...`, `롤백 스크립트...` | `GenerateDeploymentScriptCommand`, `GenerateRollbackScriptCommand` |
| `develop ▾` | `브랜치 전환...`, `새 브랜치...` | `SwitchBranchCommand`, `CreateBranchCommand` |

지금 버튼에 달린 ToolTip 문구는 메뉴 항목의 ToolTip으로 그대로 옮긴다.

**함정 둘.**

1. `ContextMenu`는 별도 시각 트리라 `DataContext`를 상속받지 않는다. 그대로 두면 항목의 `Command`
   바인딩이 조용히 실패해 **메뉴는 뜨는데 눌러도 아무 일이 없다.** 여는 순간
   `menu.PlacementTarget = button; menu.DataContext = button.DataContext;`를 코드비하인드에서 준다.
2. 메뉴를 여는 버튼 자체에는 명령이 없어 `CanExecute`로 잠기지 않는다. 항목이 모두 잠겨 있어도
   메뉴는 열린다 — 배포·감사 클론에서 `develop ▾`를 열면 두 항목이 잠긴 채 보인다. 이것은 의도다
   (고정 브랜치라는 사실을 화면이 말한다). 다만 **작업 중(`IsBusy`)에는 메뉴를 여는 버튼도 잠근다.**
   열린 메뉴가 작업 종료 뒤 남는 경로를 만들지 않기 위해서다.

색: `ContextMenu`·`MenuItem`은 VS가 칠해 주지 않는다. `Background`/`Foreground`에
`VsBrushes.ToolWindowBackgroundKey`/`ToolWindowTextKey`를 준다. XAML의 `DynamicResource`가 아니라 **여는
순간 버튼에서 `TryFindResource`로 찾아 넣는다** — `ContextMenu`는 열리기 전에는 컨트롤의 리소스 트리에
붙어 있지 않아 키가 풀리는 시점을 보장할 수 없고, 열 때마다 다시 찾으므로 테마를 바꿔도 다음에 열 때 따라간다. 체크박스에서
겪은 "어두운 테마에서 글씨가 사라진다"(`AuthorToggle` 주석)와 같은 결함이 메뉴에서 되풀이되지 않게 한다.

### 3.3 ViewModel에 더하는 것

재배치이므로 명령은 더하지 않는다. 화면이 새로 읽는 값만 더한다.

| 속성 | 뜻 | 대체하는 것 |
| --- | --- | --- |
| `RemoteStatus? LastRemoteStatus` | 마지막 원격 확인 결과. 지금 `RemoteStatusText`를 지우는 여섯 자리에서 똑같이 `null`이 된다 | `RemoteStatusText`, `HasRemoteStatus` |
| `string PullButtonText` | 확인 전 `Pull`, 확인 후 `Pull ↓{BehindBy}` | — |
| `string PushButtonText` | 확인 전 `Push`, 확인 후 `Push ↑{AheadBy}` | — |
| `int CheckedCount` | `Changes.Count(c => c.IsSelected)` | — |

숫자가 0이어도 붙인다(`Pull ↓0`). "확인했고 받을 것이 없다"와 "확인하지 않았다"를 가르는 것이 이
숫자의 목적이다. Pull·Push 버튼의 ToolTip에 "숫자는 마지막으로 '원격 확인'을 누른 시점의 값입니다.
자동으로 갱신되지 않습니다."를 덧붙인다(지금 `RemoteStatusLabel`의 ToolTip).

`CheckedCount`는 `ChangeItemViewModel.IsSelected`의 변경을 들어야 갱신된다. 지금 ViewModel은 항목의
`PropertyChanged`를 구독하지 않는다 — 항목을 `Changes`에 넣고 뺄 때 구독을 걸고 풀며, 들은 김에
`RaiseActionCanExecuteChanged()`도 부른다. **체크를 바꿨을 때 지금 버튼 활성 상태가 제때 바뀌는지는
확인하지 않았다.** 구현 계획의 첫 작업에서 테스트로 현재 동작을 먼저 고정하고, 이미 갱신되고 있다면
이중으로 부르지 않는다.

### 3.4 바뀌지 않는 것

- 모든 명령의 `CanExecute`, 확인 대화상자, 알림 문구, 백그라운드 스케줄링.
- 진행 표시·행동 안내·세 배너·경고 배너·차단 오버레이의 자리와 규칙. 차단 오버레이가 도구 줄까지
  덮어 클릭을 삼킨다는 테스트(`BlockOverlay_SwallowsClicksOnTheToolbar_WhenBlocked`)는 새 배치에서도
  통과해야 한다 — 메뉴를 여는 버튼도 오버레이 아래에 있으므로 눌리지 않는다.
- 초기화 오버레이, 이력 탭.
- 배포·감사 패널 전체 — 0.8.0의 병합 영역(`병합할 브랜치 확인`·`병합`·브랜치 목록·미리보기)을 포함한다(2.7).
  `DeploymentPanelGrid` 안쪽 XAML과 `DeploymentViewModel`을 고치지 않는다.

## 4. 검증

### 4.1 자동 테스트

레이아웃은 `TopRowLayoutTests`처럼 실제 컨트롤을 STA로 배치해 좌표로 본다.

1. `BranchMenuButton`이 버전 왼쪽 같은 줄에 있다 / 브랜치가 없으면 숨는다 — 기존 `BranchLabel` 두
   테스트를 옮긴다.
2. `RemoteStatusLabel` 두 테스트는 지운다. 대신 ViewModel 테스트: 원격 확인 전 `PullButtonText == "Pull"`,
   `RemoteStatus(2, 1)`(생성자 순서는 `aheadBy, behindBy`) 뒤 `"Pull ↓1"`/`"Push ↑2"`, 대상 변경·Pull·Push·확인 실패·브랜치 전환 뒤 다시 `"Pull"`.
3. 동기화 줄: 폭 600에서 `PullButton`과 `RefreshButton`이 같은 줄, 폭 300에서 `PullButton`·`PushButton`·
   `CheckRemoteButton`이 **서로 같은 줄**(무리가 쪼개지지 않는다).
4. 커밋 메시지 칸이 폭 600과 900에서 폭이 달라진다(고정 240이 아니다). 안내 글자는 메시지가 비면
   보이고 채우면 숨는다.
5. `CheckedCount`: 항목 3개 중 2개 체크 → 2, 하나 더 해제 → 1. 해제로 0이 되면 `DiscardCommand.CanExecute`가
   false.
6. 세 메뉴: 코드비하인드가 열 때 `DataContext`가 버튼의 것과 같다. 항목의 `Command`가 기대한 명령 인스턴스다.
7. 메뉴 색: `AuthorToggle_TakesItsForegroundFromTheShellTheme`와 같은 방식(Magenta)으로 `ContextMenu`의
   `Foreground`가 셸 브러시인지.
8. 기존 `BlockOverlay_*` 세 테스트가 그대로 통과한다.
9. 배포(`Deploy`) 대상: `BranchMenuButton`이 보이고, 준비한 메뉴의 두 항목이 잠겨 있다(`Command.CanExecute`가
   false). 변경 목록 도구 줄(`PullButton` 등)은 보이지 않고 배포 패널이 보인다 — 새 도구 줄이
   `ShowChangeList` 안에 들어 있어 배포 화면에 새어 나오지 않는지를 가른다.
10. 기존 `DeploymentPanelLayoutTests`와 `DeploymentViewModelMergeTests`가 그대로 통과한다.

### 4.2 SSMS 21에서 직접 누를 것

CI는 WPF 렌더링을 검증하지 않는다. 아래를 누르기 전에는 "동작한다"고 말하지 않는다.

1. 밝은 테마·어두운 테마 각각에서 세 메뉴를 열어 글씨가 읽히는지, 항목에 마우스를 올렸을 때 강조가 보이는지.
2. 도구 창을 좁게 도킹해 동기화 무리가 통째로 내려가는지. 대상 표시("Windows 인증")가 더 이상 잘리지 않는지.
3. `새로고침 ▾` → `전체 다시 추출` / `스크립트 ▾` → 두 항목 / `develop ▾` → 두 항목이 지금 버튼과 같은 결과를 내는지.
4. 원격 확인 → 숫자가 버튼에 붙는지, Pull 뒤 사라지는지, 다른 DB를 고르면 사라지는지.
5. 체크를 모두 해제하면 `되돌리기`·`무시`가 잠기고, `스크립트 ▾`는 열리되 두 항목이 잠겨 보이는지(3.2의 2).
6. 배포·감사 클론에서 `develop ▾`/`master ▾`를 열면 두 항목이 잠겨 보이고 ToolTip이 이유를 말하는지.
   윗줄 브랜치 버튼이 병합 영역 머리글과 겹치거나 가리지 않는지.
7. 작업 중에 세 메뉴 버튼이 잠기는지. 배포 클론에서 `병합할 브랜치 확인`이 도는 동안 윗줄 브랜치 버튼도 잠기는지
   (배포 패널과 개발 화면은 같은 `BusyState`를 쓴다).
8. 배포 클론에서 병합 → "차이 검사 시작" 확인까지 한 바퀴가 0.8.0과 똑같이 도는지(회귀 확인).

- `README.md`: "원격 확인"의 "`받을 커밋 n개 · 올릴 커밋 n개` 를 상단에 띄웁니다"를 "Pull·Push 버튼에
  `↓n`·`↑n`으로 붙입니다"로. `전체 다시 추출`·`배포 스크립트`·`롤백 스크립트`·`새 브랜치`·`브랜치 전환`을

  이름만 지나가며 부르는 곳은 두지 않는다 — 메뉴 항목의 이름이 같으므로 찾을 수 있다.

  문장(브랜치 전환 위치, 원격 확인 숫자, 스크립트, 전체 다시 추출)을 고친다. 머리 버전도 올린다 — 0.8.0 때
  0.7.2로 남았다. 배포 패널 설명은 2.7에 따라 그대로 둔다.
- `docs/setup-checklist.md`: 새 버전 절에 4.2의 여덟 항목. 기존 항목 중 버튼 이름으로 찾는 문장(예:
  0.4.0 절 "원격 확인의 숫자")은 새 자리로 고친다. 병합 절(0.8.0)의 버튼 이름은 바뀌지 않으므로 두지 않는다.
- `source.extension.vsixmanifest`: 0.8.0(병합) → **0.9.0**. 병합이 먼저 나갔으므로 병합 문서의 버전은 건드리지 않는다.
