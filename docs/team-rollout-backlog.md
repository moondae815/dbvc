# 팀 배포 백로그

DBVC를 팀에 공유하기 위해 남은 일. 2026-09-04 기준이며, P0 둘(UTF-8 전환, MarkProcessed 실패
알림 + GRANT)은 0.5.16으로 끝났다.

## 팀 환경

이 백로그의 우선순위는 아래 환경을 전제로 매겼다. 환경이 다르면 순서가 달라진다.

- 개발자 20명, DBA 3명
- 폐쇄망 GitLab (마켓플레이스·자동 업데이트 없음)
- 공용 개발 DB 1대, 공용 테스트 DB 1대, 공용 운영 DB 1대 — **개인 DB가 없다.**
  한 DB의 `DBVC_ChangeLog`를 23명이 함께 쓴다는 뜻이고, 아래 6·7번이 여기서 나온다.

## 배포 전에 막을 것

### 1. 커밋 작성자가 전원 `DBVC User <dbvc@example.com>`

`GitManager.cs`의 `DefaultAuthorName` 폴백이다. 클론에 `git config user.name`이 없으면 여기로
떨어진다. 20명이 같은 저장소에 커밋하는데 `git blame`과 GitLab MR 작성자가 전부 같은 이름이면
팀 공유의 목적 절반이 사라진다. P1 중 가장 싸고 효과가 크다.

선택지: 클론 시점에 이름·메일을 묻거나, 최소한 폴백으로 떨어졌을 때 배너로 알린다.

### 2. `.vsix` 배포·갱신 채널

폐쇄망이라 자동 업데이트가 없다. 지금은 파일 복사 + 수동 설치뿐이고, 누가 어떤 버전을 쓰는지
알 방법도 없다. 0.5.15 → 0.5.16처럼 고치고 재배포할 일이 반드시 또 생기는데, 그때 23명에게
어떻게 알릴지가 정해져 있지 않다. 코드가 아니라 정책 결정이다.

## 배포 후에 채워도 되는 것

### 3. 작업 트리 되돌리기(discard)

`GitManager`에 discard/reset이 없다. 잘못 추출된 `.sql`을 버리려면 SSMS 밖에서
`git checkout --`을 쳐야 한다. DBA 3명은 몰라도 개발자 20명에게는 벽이다.

### 4. 브랜치 전환

없다. **정책으로 닫기를 권한다** — "개발 클론은 develop 고정". 도구에 넣으면 공용 DB의 상태와
체크아웃된 브랜치가 어긋나는 사고가 열린다. 공용 DB가 하나뿐이라 이 위험이 특히 크다.

### 5. ChangeLog 보존 정책

`DBVC_ChangeLog` 정리가 아예 없다. 공용 개발 DB에서 무한히 증가한다.

### 6. 미채택자 행 누적

DBVC를 쓰지 않는 사람의 DDL도 트리거가 기록하는데, 아무도 커밋하지 않으므로 `IsProcessed = 0`
으로 영원히 남아 **모두의** 새로고침 목록을 오염시킨다. 5번과 한 몸으로 설계해야 한다.

### 7. 병합 충돌 해결

도구 밖이다. GitLab이나 외부 도구로 푼다. 당분간 이대로 두는 것이 맞다.

### 8. Object Explorer 아이콘 오버레이 (Feature 10)

공개 확장점이 없어 보류. 사유는
`docs/superpowers/plans/2026-08-01-dbvc-object-explorer-overlay.md`에 있다. 그대로 둔다.

## 남은 검증
